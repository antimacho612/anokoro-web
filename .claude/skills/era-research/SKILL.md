# あのころ Web の時代調査

解説の中身を「その年の目線で、裏付けのある事実」にするための調査をする。
成果物は報告書と、組み込みの提案（差分案）まで。`content/help` と `packages/era-data` は書き換えない。組み込むかは人が決める。

## 0. 範囲を決める

引数から対象を決める。引数がなければ、次のどれにするかを人に聞いてから始める。

- トピック ID（`content/help/*.md` の `id`）: そのトピックの全節
- 年の範囲（例: `1995-1999`）: その期間の全トピック
- テーマ（例: `Flash の盛衰`）: 関連するトピックを横断
- `全体`: トピックごとに分けて順に進める（1 回で全部やらない）

## 1. 現状を把握する

調べる前に、次を読んで「いま何と書いてあるか」を一覧にする。

- `content/help/*.md`: 各節の主張と、`<!-- years: … -->` の範囲
- `packages/era-data/src/`: 機能年表（`availableFrom`、`partialFrom`、廃れた扱い）、回線、解像度、外観の年。各行の根拠 URL
- `apps/web/src/kit/parts/parts.ts` の `tip`、`apps/web/src/kit/line/line-notes.ts`

主張は 1 文 1 件に分け、「年・数値・固有名詞・因果」を含むものを検証対象にする。

## 2. 収集する

時期とテーマで分け、Agent ツールで調査役を並列に立てる（1 回に 3〜5 体まで）。各調査役への指示には、次の 4 つを必ず入れる。

1. 調べる時期とテーマ、確かめたい主張の一覧
2. 下の「出典の格付け」と「禁止事項」
3. 既存の主張の裏付けだけでなく、**書かれていない重要な出来事・流行・廃れ**も探すこと
4. 返す形式は「主張／年月（精度）／出典 URL と格付け／確度」の表

集める観点：

- **登場と普及**: 発表、提供開始、日本での開始、普及の目安（利用率や世帯普及率が何%を超えたか）
- **流行の山**: 流行語、雑誌の特集、サービスの会員数の推移
- **廃れ**: 提供終了、非推奨化、シェアの逆転、「もう使わない」が常識になった時期
- **日本固有の事情**: 海外と時期がずれるもの（携帯サイト、テレホーダイ、文字コード、掲示板文化など）
- **ページ作りへの影響**: その年の個人サイトや企業サイトの作り方が、何によってどう変わったか

## 3. 裏取りする

### 出典の格付け

| 格       | 例                                                                                                                                                                                                       |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A 一次   | 標準化団体の勧告（W3C、IETF）、企業の当時のプレスリリース、官公庁の統計（総務省「通信利用動向調査」「情報通信白書」）、製品の公式リリースノート、ウェブ・アーカイブ（Wayback Machine）に残る当時のページ |
| B 準一次 | 当時の報道（INTERNET Watch、ASCII、ITmedia、日経系などの当時の記事）、当事者の回顧記事                                                                                                                   |
| C 二次   | 後年のまとめ記事、Wikipedia（出典を辿る入口にだけ使い、そのまま根拠にしない）                                                                                                                            |
| D 不可   | 出典のない個人ブログ、記憶だけの記述、AI が生成した文章                                                                                                                                                  |

### 確度

- **確定**: A が 1 件以上、または独立した B が 2 件以上で一致
- **有力**: B が 1 件、または C が複数で一致し反証がない
- **未確認**: C だけ、または出典同士が食い違う

日付は精度も書く（「2001-09」「2001 年」「2000 年代前半」）。統計は調査名、調査年、値をそろえて書く。

### 反証の確認

収集とは別の調査役を 1 体立て、確度が「確定」「有力」の主張に反証を探させる。食い違いが見つかったら両方の出典を並べ、どちらを採るかの理由を書く。

## 4. 組み込みの是非を判定する

各主張・各候補について、次の基準で「採用／条件付き採用／不採用」を決める。

| 基準                 | 見ること                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| 裏付け               | 確度が「確定」か。「有力」は条件付き、「未確認」は不採用                                       |
| 時代の目線           | 選んだ年の人が知り得たことか。後年の出来事は終わりの年以降にしか出さない                       |
| 日本の Web との関係  | 1995〜2015 年の日本でページを作る・見る体験に関わるか                                          |
| サービスとのつながり | 時代チェッカーの警告、パーツ、回線、解像度、外観、時代まちがいさがしの出題のどれかに結びつくか |
| 権利                 | 自分の言葉で書けるか。実在の製品・サービスは名前を挙げるだけで、ロゴやデザインを使わない       |
| 粒度                 | 1 節に収まるか。細かすぎるものは年表の 1 行にする                                              |

採用するものは、置き場所を決める：

- 解説の本文（どのトピックのどの節か。新しい節か）と、その節の `<!-- years: 始め-終わり -->`
- 年表（`10-timeline.md` の項目）
- `packages/era-data` の行の追加や年の修正（根拠 URL つき）
- パーツの豆知識、回線の説明

## 5. 報告書を書く

`docs/research/<YYYY-MM-DD>-<対象>.md` に、[report-template.md](report-template.md) の形で書く。
最後に、人が判断すべきこと（採るか迷うもの、出典が食い違うもの、年の範囲を変えると表示が大きく変わるもの）を箇条書きで渡す。

## 禁止事項

- `content/help`、`packages/era-data`、そのほかのコードを書き換えない。差分案は報告書の中に書く
- 出典の文章を引き写さない。要約は自分の言葉で、元より十分短くする。引用が要るときも 1 出典につき 15 語未満を 1 か所まで
- 記憶だけで年や数字を書かない。出典が見つからなければ「未確認」と書く
- 出典 URL を推測で作らない。開いて内容を確かめたものだけを書く
- 当時のサイトのデザイン、ロゴ、画像、文言を再現する提案をしない
- 個人（当時の個人サイトの管理人など）を特定する情報を集めない
