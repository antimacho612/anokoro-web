## M1.5 時代まちがいさがし

ある年のページに、その年にはまだ使えなかった技術が 1 か所だけ混ざっている。それを見つける遊び。
仕様書とプロトタイプにない機能なので、M1.5-01 で仕様を書き、以降はその仕様を完了条件の基準にする。

決まっていること：

- 「使えなかった」の基準は `era-data` の `availableFrom` に合わせる
- 描画しても見た目が変わらない技術は、ソース表示モードでだけ出題する
- 出題するのは技術だけ。実在の製品やサービスは出さない
- 第 1 段階なので、サーバーを使わずクライアントだけで完結させる
- `partialFrom` 以上 `availableFrom` 未満の年には、その技術を出題しない
- 答えられるのは 3 回まで。3 回間違えたら答えの場所を強調し、その `topic` の解説を開けるようにする。ヒントは出さない
- 画面は S-09「時代まちがいさがし」、URL は `/quiz`。`apps/web` のマルチページに `quiz/index.html` を足す
- 作成キットからの入口は 3 か所：タイムマシンバーの横のボタン、ヘルプ(H)メニュー、解説の末尾（その `topic` の技術に絞って出題する）

- [ ] **M1.5-01 仕様の追記**：画面、出題の規則、正解の判定、解説への導線を仕様書に書く
- [ ] **M1.5-02 お題データ**：年ごとのお題ページ（自作テンプレート）を、第 1 段階の 6 種類（個人ホームページ、企業・お店の公式サイト、ディレクトリ型ポータル、掲示板、ネットショップ、ブログ）で用意し、その年にまだない種類は出題しない。あわせて埋め込める時代外れの技術の候補を用意する。すべての組み合わせで `checkEra` の違反がちょうど 1 件になり、その `topic` が答えと一致することをテストする
- [ ] **M1.5-03 出題の生成**：シード付き乱数で、年、お題、時代外れの技術を選ぶ純粋関数。`topic` を指定すると、その技術だけから選ぶ。「今日の 1 問」はアプリ側で日付からシードを作って渡す
- [ ] **M1.5-04 遊ぶ画面**：S-09（`/quiz`）と作成キットからの入口 3 か所。表示モード（`sandbox="allow-same-origin"` の iframe）とソース表示モードの切替、要素や行をクリックして答える、正解したらルールの `topic` から解説を開く
- [ ] **M1.5-05 回線の出題**：ページは正しいのに、回線だけが時代に合わない（例：1997 年なのに読み込みが一瞬で終わる）問題を `netsim` で出す
- [ ] **M1.5-06 E2E**：出題、正解、不正解、解説を開くまでの流れを Playwright で確かめる

## M2 ローカル保存と共有（第 1 段階の公開）

マイルストーンの完了条件：攻撃文字列入りの URL やファイルでも、スクリプトの実行がゼロ。

着手する前に決めること（12 章）：ドメイン、URL 共有の長さの目安。

- [ ] **M2-01 サイトの保存**：`packages/site-store` で IndexedDB への保存と読み出し（F-13、5.1）
- [ ] **M2-02 共有データ**：`packages/share-codec` で圧縮、展開、検証。往復で一致し、壊れた入力や巨大な入力を拒否することをテストする（5.2）
- [ ] **M2-03 マイコンピュータ**：サイトとページの一覧、複数ページの編集、自動保存（F-14、S-02、3.6）

- [ ] **M2-05 見本サイト**：6 種類の見本サイトを 1 つずつバンドルし、マイコンピュータの「見本サイト」フォルダと閲覧画面 `/view?sample=<id>` で見られるようにする。ゴールデンテストで、その年の警告がゼロであることを確かめる（F-27、S-03、11.2）

- [ ] **M2-08 ファイル入出力**：書き出しと読み込み、上書きか追加かの選択、保存の案内（F-17、F-18）
