# 作業チケット（M1〜M2）

`docs/spec/11-plan-testing.md` の 11.1 節の作業分割をチケットにしたもの。
上から順に 1 つずつ進め、終わるたびに人が動作を確かめる。

各チケットに共通する完了条件：

- `vp check` と `vp test` が通る
- プロトタイプ（`docs/spec/prototype.html`）と同じ振る舞いをする。違う場合は、仕様書に書いてある差分だけにする

## M1 作成キットの本実装

マイルストーンの完了条件：時代チェッカーのゴールデンテストと、回線経由表示の E2E が通る。

着手する前に決めること（12 章）：疑似 URL のホスト名、対象の最終年、機能年表・回線・解像度の年の裏付け。

- [x] **M1-01 モノレポの雛形**：`vp create`、pnpm workspaces、TypeScript、`vp check`、`vp test`、GitHub Actions（`setup-vp`）。`apps/web` は `kit/index.html` と `view/index.html` を出すマルチページ構成にし、`base` を切り替えられるようにする（4 章、4.1、4.2、4.4）。Cloudflare の Vite プラグインとの組み合わせ確認は M3 の着手時に回す
- [ ] **M1-02 素材とデータ**：`packages/assets` に素材 SVG とマニフェスト（名前、疑似バイト数、作者、ライセンス）を置く。`packages/era-data` に機能年表、回線と解像度の年表を置く（3.5、7.9、8.1、8.5）
- [ ] **M1-03 時代チェッカー**：`packages/era-checker` に `checkEra` を実装し、ゴールデンテストを書く。1996、2003、2008、2012 年で同じ入力を検査する（7 章、11.2）
- [ ] **M1-04 回線シミュレーター**：`packages/netsim` に読み込みスケジューラと、差し替え可能な時計を実装する。同時接続 2 件、帯域の等分、CGI の待ち、中止をテストする（8.4）
- [ ] **M1-05 接続音**：`packages/modem-sound` で接続音を合成する。シード付き乱数を使う（8.6）
- [ ] **M1-06 ウィンドウとレイアウト**：`apps/web` にクラシック風ウィンドウの部品、2 列と 1 列のレイアウト、タイムマシンバーを作る（3.2、3.3、3.5）
- [ ] **M1-07 編集とローカル表示**：メモ帳、パーツ箱、素材集、ローカル表示、解像度の切替（F-01、F-02、F-04〜F-06）
- [ ] **M1-08 回線**：回線ウィンドウ、ダイヤルアップ、通話料、回線経由表示のアダプタ、ローカルカウンターとキリ番（F-07〜F-09、F-12、8 章）
- [ ] **M1-09 解説**：`content/help` とヘルプウィンドウ、警告から解説を開くリンク、年による表示の絞り込み（F-10、10.2）
- [ ] **M1-10 該当行への移動**：警告をクリックすると、メモ帳の該当行にカーソルが移る（3.2、7.1 の `locations`）

## M2 ローカル保存と共有（第 1 段階の公開）

マイルストーンの完了条件：攻撃文字列入りの URL やファイルでも、スクリプトの実行がゼロ。

着手する前に決めること（12 章）：ドメイン、URL 共有の長さの目安。

- [ ] **M2-01 サイトの保存**：`packages/site-store` で IndexedDB への保存と読み出し（F-13、5.1）
- [ ] **M2-02 共有データ**：`packages/share-codec` で圧縮、展開、検証。往復で一致し、壊れた入力や巨大な入力を拒否することをテストする（5.2）
- [ ] **M2-03 マイコンピュータ**：サイトとページの一覧、複数ページの編集、自動保存（F-14、S-02、3.6）
- [ ] **M2-04 ページ間リンク**：疑似ブラウザでサイト内リンクをたどる。戻ると進む（F-15、7.7）
- [ ] **M2-05 URL共有**：共有ダイアログと閲覧画面 `/view`、「キットに取り込む」（F-16、S-03）
- [ ] **M2-06 ファイル入出力**：書き出しと読み込み、上書きか追加かの選択、保存の案内（F-17、F-18）
- [ ] **M2-07 デプロイ**：GitHub Actions で GitHub Pages にデプロイし、各 HTML に `meta` 要素で CSP を付ける（4章、9.2）。攻撃文字列の E2E（9.5）を通す

M3 以降は `docs/spec/11-plan-testing.md` の図と、`docs/spec/02-requirements.md` の 2.1 節の機能要件を参照する。
